# IPv6 в Android-клиенте TiredVPN

В приложении отдельно настраиваются IPv6-подключение к серверу и передача IPv6-трафика внутри VPN. Для результата с публичным IPv6 на test-ipv6.com нужна вторая настройка.

## Включить IPv6 внутри туннеля

1. Убедитесь, что выходной сервер TiredVPN поддерживает dual-stack TUN: в его команде задан `-ip-pool-v6`, настроены NAT66 и IPv6 forwarding. [Инструкция для сервера](https://github.com/igor04091968/tiredvpn/blob/main/docs/ipv6-setup-ru.md).
2. В TiredVPN откройте параметры именно того сервера/профиля, через который подключаетесь.
3. Включите **«IPv6 в туннеле (двойной стек)»** и сохраните профиль.
4. Отключите и снова подключите VPN, чтобы клиент заново согласовал IPv6-адреса с сервером.
5. Откройте [test-ipv6.com](https://test-ipv6.com) в приложении, которое проходит через VPN.

В Android-клиенте этот переключатель по умолчанию выключен и хранится в профиле сервера. Если профиль импортирован заново, проверьте значение после импорта. Для экспорта конфигурации включённое значение представляется полем `tunnelIpv6: "dual"`.

IPv6 в туннеле работает и тогда, когда телефон соединяется с VPN-сервером по IPv4. Поэтому обычно не требуется заполнять «Адрес IPv6», выключать резервный IPv4 или добиваться собственного IPv6 у мобильного оператора.

## IPv6-транспорт до сервера — отдельная настройка

Поля **«Адрес IPv6»**, **«Предпочитать IPv6»** и **«Резервный IPv4»** управляют внешним соединением телефона с сервером. Они не включают IPv6 внутри туннеля и не меняют публичный адрес выхода.

Если на мобильной сети доступен IPv6, сервер слушает IPv6 и задан его адрес, в поле «Адрес IPv6» укажите адрес с портом в формате `[2001:db8::10]:443`. Сохраните IPv4-адрес или резервный IPv4, если нужен автоматический переход на IPv4 при недоступности IPv6. Скобки вокруг IPv6-литерала обязательны.

## Проверить результат

После переподключения test-ipv6.com должен показать IPv4 и IPv6 адреса выхода TiredVPN-сервера. Для полного туннеля публичный IPv6 должен принадлежать серверу; нативный адрес мобильного оператора не должен использоваться как выход.

Если страница показывает IPv4 VPN-сервера и **No IPv6**:

- проверьте, что включён именно переключатель «IPv6 в туннеле (двойной стек)», а не «Предпочитать IPv6»;
- убедитесь, что переключатель включён у активного профиля и после его изменения VPN переподключён;
- проверьте, что Chrome не исключён из VPN в настройке раздельной маршрутизации приложений;
- на сервере проверьте журнал: он должен показать выдачу клиенту dual-stack IPv6-адреса. Сам факт подключения телефона к IPv6-адресу сервера этого не доказывает.

Если переключателя нет, обновите приложение до версии, в которой поле `tunnelIpv6` и режим `-tun-ipv6 dual` поддерживаются. В релизе форка [1.12.1-igor.8](https://github.com/igor04091968/tiredvpn-android/releases/tag/v1.12.1-igor.8) этот переключатель уже есть; пересборка APK для включения серверного IPv6 не нужна.

## MTU

Оставьте поле MTU пустым: интерфейс возьмёт значение ядра, обычно 1280. Для IPv6 нельзя опускать MTU интерфейса ниже 1280. Один TUN использует общий MTU для IPv4 и IPv6; при MTU 1280 ограничение TCP MSS составляет соответственно 1240 и 1220.

Пользовательское значение 1280–9000 служит верхней границей. Android не устанавливает MTU интерфейса выше значения, полученного от ядра. Некорректные значения импортированного профиля заменяются автоматическим режимом; те же проверки действуют при подготовке параметров запуска ядра. Смена сети сохраняет параметры текущей конфигурации, но сама по себе не измеряет PMTU.

Исправления MSS IPv6 и возврата Packet Too Big находятся во встроенном Go-ядре. Для их получения нужен APK с пересобранными JNI-библиотеками из соответствующего исправленного core checkout. Изменение Kotlin-файлов или серверного бинарника не обновляет уже установленную библиотеку на телефоне.

Повышение MTU проверяйте на доступном узле отдельно для IPv4/IPv6, скачивания/отдачи и UDP. После смены Wi-Fi на мобильную сеть повторите тест. Успешный ответ большого файла не гарантирует проходимость всех внешних маршрутов. Правка оставляет MTU 1280 по умолчанию; измерений прироста скорости на телефоне пока нет.
